# 字幕获取实验记录

## 当前结论

不使用音频转写。字幕获取优先级调整为：

1. 官网 / Substack / 官方页面 transcript。
2. Chrome 打开官方 YouTube 视频，使用 YouTube 自带 transcript 面板。
3. Chrome + Language Reactor 右侧字幕面板兜底。
4. Spotify transcript 插件兜底。
5. 仍无 transcript 时标记为 `transcript_missing`，不做事实性深度总结。

## 工具测试结果

### youtube-transcript-api

结果：不可作为主链。

原因：在当前运行环境中请求 YouTube 字幕时触发 `RequestBlocked`。这不代表用户本机浏览器不可用，而是说明服务器式请求容易被 YouTube 拦截。

### yt-dlp

结果：不可作为默认主链。

原因：无浏览器身份时，YouTube 返回 “Sign in to confirm you’re not a bot”。不建议使用 `--cookies-from-browser`，因为这会读取浏览器 cookies，不适合放进默认自动化。

### Chrome + Language Reactor

结果：可用，适合作为低成本字幕来源。

已验证：

- Dwarkesh 视频 `https://www.youtube.com/watch?v=oIk3R-sMX5o`：
  - Language Reactor 能显示大量字幕片段。
  - 页面中也存在 YouTube caption tracks。

- All-In 视频 `https://www.youtube.com/watch?v=HGbA6ze0_3M`：
  - YouTube 搜索能准确匹配官方视频。
  - 视频有英文自动字幕轨道。
  - Language Reactor 能显示字幕片段。
  - 按 `0` 可把视频与字幕同步回开头，前几条字幕从 `idx=0` 开始。

## 需要注意的问题

- Language Reactor 面板是虚拟滚动，页面上只渲染当前附近的字幕片段。
- 采集完整 transcript 时，需要：
  1. 打开官方 YouTube 视频。
  2. 等 Language Reactor 加载。
  3. 点击/聚焦播放器。
  4. 按 `0` 回到开头。
  5. 缓慢滚动右侧字幕面板，按 `data-index` 去重收集。
  6. 检查 `idx` 是否连续，缺失则补滚动。
- 自动化接口里直接设置 `scrollTop` 不可靠，需要用真实滚动或 YouTube 自带 transcript 面板。

## 下一步建议

先实现 YouTube 视频匹配与字幕状态判断：

- episode 标题搜索 YouTube。
- 只接受官方频道或白名单频道。
- 校验标题、频道、发布时间、时长。
- 打开视频后判断：
  - 是否有 YouTube transcript 按钮。
  - 是否有 Language Reactor 面板。
  - 是否能拿到字幕片段。

在字幕获取稳定前，不要批量跑 26 条，先用 3-5 条高可行性播客做样本。
