# Gemini 研报复查清单

用于检查 Gemini 生成的播客情报研报是否严格基于本次 episode 和 transcript，同时允许合理使用背景资料进行深度解析。

## 1. Episode 覆盖检查

- 研报中的 episode 数量必须等于 `Episode Manifest` 数量。
- 研报中的 episode 标题必须全部来自 Manifest。
- 不允许出现 Manifest 之外的旧节目、相似节目或同频道其他节目。
- 顺序必须与 Manifest 一致：按 episode 发布时间倒序，最新在前。

## 2. 链接与来源检查

- 每篇必须有准确原始标题。
- 每篇必须有准确原始链接。
- 每篇必须标注 transcript 来源。
- 不允许出现“推测链接格式”。

## 3. Transcript 证据检查

每篇 episode 至少检查：

- 是否有 3 个以上证据锚点。
- 关键金句是否能在 transcript 中找到或高度贴近原文。
- 人名、公司名、产品名、金额、日期、技术名词是否出现在 transcript 或可靠背景资料中。
- 如果 transcript 缺失或质量差，是否明确标注“待核验”，而不是强行总结。

## 4. 背景资料边界检查

允许背景资料，但必须满足：

- 背景资料与本 episode 主题直接相关。
- 背景资料不得被写成嘉宾原话。
- 背景资料不得替代 episode 摘要。
- 背景资料中的事实如果不能确认，需要标注“背景资料显示”或“待核验”。

## 5. 分析判断检查

- 深度专题分析必须能回到至少 2 个 episode 的内容。
- 第二层思维可以推演，但必须使用“可能意味着”“这提示”“可以理解为”等措辞。
- 不允许把单一嘉宾观点写成全行业定论。
- 不允许为了制造宏大叙事而虚构因果链。

## 6. 常见错误拦截

重点检查以下问题：

- 数量不一致。
- 漏掉某个 episode。
- 加入旧 episode。
- 把标题相似的 YouTube 视频误认为本集。
- 把新闻背景写成播客内容。
- 金句不是原话，也没有时间戳。
- 人名职位编造。
- 公司数据或金额没有来源。
- 结论明显超出 transcript 支撑范围。

## 7. 验收结果

复查后输出：

```text
复查结论：通过 / 需修改 / 不通过
Episode 数量：Manifest X 篇，研报 Y 篇
排序检查：通过 / 不通过
链接检查：通过 / 不通过
Transcript 证据检查：通过 / 需人工复核
高风险问题：
1. ...
2. ...
建议修改：
1. ...
2. ...
```
